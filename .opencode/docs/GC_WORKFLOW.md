# GC Workflow

Repository working flow:

1. Discover current reality from repo-local docs and code.
2. Create or update a plan in `.opencode/plans/` for non-trivial work.
3. Implement through the right specialist lane.
4. Validate with repo-appropriate checks.
5. Store evidence in `.opencode/evidence/`.
6. Route non-trivial final review to `@quality-gate`.

For repeated failures, add or improve a doc, script, gate, or skill instead of repeating ad hoc fixes.
